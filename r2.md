  🧠 Greedy Solver Algorithm Logic

  1. Core Principle: "First Available, Best Fit"

  The greedy solver uses a priority-based, earliest-available-time approach rather than global optimization.

  2. Job Processing Pipeline

  Input Jobs → Validate & Categorize → Schedule by Priority → Apply Constraints → Output Schedule

  3. Job Categorization (3 Types)

  A) NOT_ASSIGN Jobs
  - Jobs with MachineName_v = "NOT_ASSIGN"
  - Automatically routed to Subcon machine
  - Scheduled by priority order

  B) Independent Jobs
  - Jobs with no dependencies (process number = 1 or no family)
  - Can be scheduled immediately when resources available
  - Scheduled by priority order

  C) Dependency Jobs
  - Jobs that are part of a family sequence (P01 → P02 → P03)
  - Must wait for previous process in family to complete
  - Creates dependency chains

  4. Scheduling Strategy

  Priority-Based Ordering:
  sorted_jobs = sorted(jobs, key=lambda j: j.get('priority', 99))
  # Lower number = Higher priority (1 > 2 > 3)

  Machine Assignment Logic:
  1. Specific Machine Required: Use job['MachineName_v'] if specified
  2. NOT_ASSIGN: Route to Subcon
  3. Best Available: Choose least loaded compatible machine

  5. Time Slot Finding Algorithm

  Adaptive Search with Multiple Strategies:

  # Start from earliest possible time
  current_search_time = max(machine_available_time, dependency_end_time)

  # Search with increasing increments
  increment = 3600  # Start with 1 hour
  while current_search_time < max_search_time:
      if can_schedule_job(job, machine, current_search_time):
          schedule_job()
          return

      # Try time availability jump (smart skip)
      next_available = get_next_available_slot(current_search_time)
      if next_available:
          current_search_time = next_available
      else:
          current_search_time += increment  # Fallback to incremental

      # Adaptive increment (1h → 2h → 4h → ... → 24h max)
      if too_many_failures:
          increment = min(increment * 2, 86400)

  6. Constraint Enforcement

  The solver checks 4 constraint types for each placement:

  A) Machine Availability
  # No time overlap with existing jobs on same machine
  for scheduled_job in machine_schedule:
      if overlaps(new_job_time, scheduled_job_time):
          return False

  B) Operator Constraints (if specified)
  # Don't exceed max operators at any hour
  for hour in job_duration:
      if operators_in_use[hour] >= max_operators:
          return False

  C) Deadline Constraints
  # Job must finish before LCD_DATE (with grace period)
  if job_end_time > (lcd_date + grace_period):
      return False

  D) Time Availability
  # Job must start during working hours
  if not is_time_available_for_scheduling(start_time):
      return False

  7. Dependency Handling

  Family Sequence Logic:

      prev_process_key = (family, process_num - 1)
      if prev_process_key not in completed_processes:
          skip_job()  # Cannot schedule yet
      else:
          earliest_start = max(machine_available, prev_process_end_time)

  8. Overload Detection & Extended Search

  Smart Search Window Adjustment:

  10. Algorithm Flow Summary

  1. Load config from .env (15 parameters)
  2. Validate & prepare jobs (calculate processing times)
  3. Categorize jobs (NOT_ASSIGN, independent, dependency)
  4. Initialize machine availability tracking
  5. Schedule NOT_ASSIGN jobs → Subcon
  6. Schedule independent jobs by priority
  7. Schedule dependency jobs by family order
  8. For each job:
     - Find best machine
     - Search for earliest valid time slot
     - Apply all constraints
     - Update tracking structures
  9. Sort final schedule by start times
  10. Log results and unscheduled jobs

  🎯 Why "Greedy"?

  It's called "greedy" because it makes locally optimal choices at each step:
  - Takes the first available time slot that satisfies constraints
  - Chooses the least loaded machine when multiple options exist
  - Processes jobs in priority order without reconsidering earlier decisions

  This approach is fast and practical, though it may not find the globally optimal solution that CP-SAT can achieve.
